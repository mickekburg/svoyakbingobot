# quizbot — Telegram-викторина на Symfony 7 и MySQL

Одиночная викторина. Темы (кино, картины, известные люди…) описываются парой файлов — JSON-конфиг и xlsx.
Игрок выбирает тему и режим, число вариантов и число вопросов в туре, отвечает кнопками, в конце видит итог:
верно / неверно / время. При ошибке бот сразу показывает правильный ответ.

## Запуск в Docker (Windows, Docker Desktop)

Ничего, кроме Docker Desktop, ставить не нужно: PHP, зависимости и MySQL живут в контейнерах.
Команды для PowerShell, из папки проекта.

1. Создайте бота у @BotFather и скопируйте токен.
2. Подготовьте настройки и впишите токен в `docker.env`:
   ```powershell
   copy docker.env.example docker.env
   notepad docker.env
   ```
3. Соберите и запустите (первая сборка тянет образы и зависимости, несколько минут):
   ```powershell
   docker compose up --build
   ```
   При каждом старте контейнер `app` применяет миграции, импортирует темы из `data/themes` и запускает бота
   (long polling, публичный адрес не нужен). В логе должны появиться строки `[quizbot] applying database
   migrations...` и `[quizbot] importing themes...` с отчётом по режимам. Затем напишите боту `/start`.
4. Фоновый запуск: `docker compose up -d --build`, логи: `docker compose logs -f app`, остановка: `docker compose down`
   (данные MySQL сохраняются в томе; `docker compose down -v` удалит и их).

Повседневные команды:

```powershell
docker compose restart app                                  # после правки xlsx/json в data\themes: темы импортируются заново
docker compose run --rm --no-deps -e SKIP_BOOT=1 app vendor/bin/phpunit   # тесты
docker compose run --rm app php bin/console app:quiz:import films          # импорт одной темы с отчётом
docker compose exec mysql mysql -uquiz -pquiz quizbot       # консоль MySQL
```

MySQL доступен с Windows на `127.0.0.1:3307` (пользователь `quiz`, пароль `quiz`, база `quizbot`), например для
DBeaver или HeidiSQL. Код копируется в образ при сборке, поэтому после правок в `src/` нужен `docker compose up --build`;
папка `data\themes` примонтирована и правится без пересборки.

Если контейнер `app` постоянно перезапускается, посмотрите `docker compose logs app`: чаще всего это пустой или неверный
`TELEGRAM_BOT_TOKEN`.

## Запуск без Docker

Нужны PHP ≥ 8.2 (расширения gd, mbstring, pdo_mysql, zip, xml) и Composer.

```bash
composer install
docker compose up -d mysql        # MySQL 8 из compose (порт хоста 3307: впишите его в DATABASE_URL в .env.local) или свой сервер
cp .env .env.local                # впишите TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET, APP_SECRET
php bin/console doctrine:migrations:migrate -n
php bin/console doctrine:schema:validate    # маппинг и миграция должны совпадать
php bin/console app:quiz:import             # загрузить все темы из data/themes
php bin/console app:telegram:poll           # разработка: long polling, публичный адрес не нужен
```

`TELEGRAM_WEBHOOK_SECRET` — случайная строка из `A-Za-z0-9_-`. `TELEGRAM_ALLOWED_USER_IDS` — id пользователей
через запятую; пусто — играть может любой.

Если у вас MariaDB или другая версия MySQL, поменяйте `serverVersion` в `DATABASE_URL`
(например `mariadb-10.11.0`).

### Продакшен (webhook)

```bash
php bin/console app:telegram:webhook https://example.com/telegram/webhook
php bin/console app:telegram:webhook --info     # проверить состояние
```

Веб-сервер отдаёт `public/index.php`. Контроллер всегда отвечает Telegram 200 (иначе апдейт будет приходить
повторно), ошибки обработки пишутся в лог. Для закрытия брошенных туров добавьте в cron:

```
*/10 * * * * php /path/to/bin/console app:quiz:close-idle --minutes=30
```

С флагом `--notify` игрок получит итог закрытого тура.

## Как устроена тема

```
data/themes/films/
  films.json      конфиг: поля, типы, режимы
  films.xlsx      данные; первая строка — заголовки, равные ключам "fields"
  images/         картинки; в xlsx путь относительно этой папки
```

Колонки `id` в xlsx нет: элемент определяется номером строки в файле (нумерация как в Excel), поэтому ошибки
импорта и строки в базе указывают на одну и ту же строку. Повторный импорт полностью пересобирает тему
в одной транзакции; при любой ошибке в файле база не меняется.

Режим — это пара полей `by` («по чему») и `what` («что угадываем») плюс шаблон вопроса. Пример из `films.json`:

```json
{ "slug": "title_by_year", "title": "Фильм по году", "by": "year", "what": "title",
  "template": "Какой из этих фильмов снят в {value} году?" }
```

Правило генерации: правильное множество = значения `what` у всех элементов, у которых `by` совпадает со
значением вопроса; неверные варианты — уникальные значения `what` вне этого множества. Поэтому в базе может
быть сколько угодно фильмов одного года, а среди показанных вариантов правильный всегда ровно один.

Импорт печатает для каждого режима `maxOptions` — наибольшее число вариантов, которое можно предложить
игроку. Режим с `maxOptions < 2` скрывается.

### Факты в ответе (`answer_info`)

После ответа бот показывает не только верно/неверно, но и другие сведения об угаданном объекте — для заучивания.
Список полей задаётся в конфиге темы, а для отдельного режима его можно переопределить (`[]` — ничего не показывать):

```json
"answer_info": ["title", "year", "director", "actors", "genre"],
"modes": [ { "slug": "...", "answer_info": ["year"], ... } ]
```

Поля `by` и `what` самого режима автоматически пропускаются, чтобы ничего не выводилось дважды
(угадываем фильм по году — год и фильм в фактах не повторяются). Подписи берутся из `label` поля, пустые значения пропускаются.
Факты выводятся полностью, вместе с текстом в скобках.

**Картинка в ответе.** В `answer_info` можно указать и поле типа `image`: после ответа бот отдельным сообщением пришлёт
эту картинку (загрузка в Telegram один раз, дальше по `file_id`). Поле, которое уже показано в вопросе (`by` или `show`),
не повторяется. Удобно задавать список на режиме, а не на теме: например, в режиме «Картина по художнику»
`"answer_info": ["painting", "year"]` покажет картину только там, где она не выдаёт ответ. Если файла картинки нет,
тур продолжается без неё, а в логе будет предупреждение.

### Скобки в значениях (`strip_brackets_in_question` / `strip_brackets_in_answer`)

Если в ячейке стоит `Евгений Онегин (1825)`, год в вопросе или вариантах ответа станет подсказкой. Две метки у поля:

```json
"books": { "type": "list", "label": "Книги", "separator": ";",
           "strip_brackets_in_question": true, "strip_brackets_in_answer": true }
```

- `strip_brackets_in_question` — когда значение поля подставляется в вопрос (`{value}`, поле стоит в `by`), текст в скобках удаляется;
- `strip_brackets_in_answer` — когда значение поля — вариант ответа (поле стоит в `what`), текст в скобках удаляется.

Те же две метки можно ставить на **режим** (рядом с `by`, `what`, `template`) — тогда они действуют только в этом режиме:
`strip_brackets_in_question` относится к полю `by`, `strip_brackets_in_answer` — к полю `what`. Если нужно для всех режимов
сразу, ставьте метку на поле. Неизвестные ключи в конфиге (например, опечатка) дают ошибку загрузки, а не молча игнорируются.

Сравнение вариантов идёт уже по очищенному тексту, поэтому «Идиот (1869)» и «Идиот (1951)» — один вариант, и
правильный ответ по-прежнему ровно один. Метки допустимы только для полей типа `string` и `list`.

## Повторение, статистика и ответ без вариантов

**Повтор ошибок (интервальное повторение, коробки Лейтнера).** Бот помнит, как вы отвечали на каждый элемент в каждом
режиме (таблица `quiz_item_progress`, нужна миграция — Docker применяет её при старте):

- ошибка отправляет элемент в коробку 0: он будет спрошен в первую очередь в следующем туре;
- верный ответ на элемент, которому «пора повторить», поднимает его на коробку выше; паузы растут: 1, 3, 7, 16, 35 дней;
- верный ответ раньше срока (заучивание «в лоб») счётчик верных увеличивает, а коробку не двигает;
- порядок в туре: сначала то, что пора повторить (по возрастанию коробки), потом новое, потом то, что ещё рано.
  Внутри одной группы выбор случайный. «Выучено» — коробка 4 и выше.

Элемент определяется по содержимому строки, а не по номеру: прогресс переживает повторный импорт и сдвиг строк. Если
изменить саму строку (например, поправить год), её прогресс начнётся заново.

**Статистика.** Команда `/stats`: по каждой теме и режиму — сколько выучено, начато, пора повторить и доля верных ответов.

**Ответ без вариантов.** На вопрос «сколько вариантов» введите `0`: бот задаст вопрос без кнопок, ответ нужно написать
сообщением. При сверке игнорируются регистр, любые пробелы и разница между «ё» и «е» («побег из шоушенка» = «ПобегИзШоушенка»). Опечатки прощаются: одна ошибка (лишняя, пропущенная, неверная или переставленная буква) в ответе из 5–9 букв, две — в более длинных; в коротких (до 4 букв) ошибок нет. Ответы с цифрами (годы, «Брат 2») сверяются точно. С опечаткой ответ засчитывается, но бот показывает, как правильно. Верным считается любое
значение, подходящее под вопрос (например, любой фильм указанного года). Скобки удаляются, если включены
`strip_brackets_in_answer`.

### Умный или случайный подбор

После числа вопросов бот спрашивает, как подбирать вопросы: «🧠 Умный подбор» (сначала ошибки и то, что пора повторить, потом новое) или «🎲 Случайный» (порядок случайный, ошибки не учитываются). Статистика и расписание повторений ведутся в обоих случаях; «Ещё раз» повторяет выбранный способ.

## Режим «назови N элементов» (`"type": "list"`)

Вопросы вида «Назови 3 фильма 1994 года» или «Назови 5 режиссёров из Испании». Конфигурация такая же, как у обычного режима, но без `show`, `distractors`, `min_options` и `max_options`; в шаблоне обязательно есть `{n}` (сколько назвать) и `{value}`:

```json
{
  "slug": "list_titles_by_year",
  "title": "Назови фильмы года",
  "type": "list",
  "by": "year",
  "what": "title",
  "template": "Назови {n} фильмов {value} года"
}
```

Для «режиссёров из Испании» в данных нужна колонка со страной режиссёра (`by`: `country`, `what`: `director`).

- Вместо «количества вариантов» игрок выбирает, сколько элементов назвать (от 1 до размера самого большого набора, максимум 20).
- Ответы пишутся сообщениями: по одному, с новой строки или через `;` (запятая тоже разделяет, но название целиком с запятой сначала проверяется как есть). Опечатки, регистр, пробелы и «ё/е» учитываются так же, как в режиме без вариантов.
- Каждый названный верно элемент даёт +1 к «верным», каждая неудачная попытка +1 к «неверным». Повтор уже названного не считается ни тем, ни другим.
- Сообщение с вопросом обновляется: «Названо 2 из 3», список названного, отметки ✅ / ❌ (нет в списке) / ↩️ (уже называли).
- Кнопка «Хватит, дальше» закрывает вопрос; показываются до 10 из оставшихся подходящих ответов.
- Вопрос считается выученным, только если названо ровно столько, сколько просили. Прогресс повторения (Leitner) ведётся по значению `by` (год, страна), а не по отдельным элементам.

## Страница статистики

`/stats` — открытая HTML-страница без входа: карточки с итогами, график «вопросов по дням» по игрокам, таблица игроков (туры, вопросы, % верных, время, выучено, последняя игра) и таблица по дням за последние 30 дней. Показываются только имена и счётчики, без id и логинов. Страница не индексируется (`noindex`), главной страницы у сайта нет.

- В Docker: `docker compose up -d` поднимает сервис `web`, страница доступна на http://localhost:8080/stats.
- На сервере: направьте веб-сервер (nginx + php-fpm) на `public/index.php`, как для webhook, страница будет по адресу `https://ваш-домен/stats`.
- Дни режутся по часовому поясу из `STATS_TIMEZONE` (например `Asia/Yekaterinburg`); если не задан, берётся пояс сервера.

## Тесты

```bash
vendor/bin/phpunit          # после composer install
php tests/standalone.php    # то же без vendor/: игровая логика и бот на in-memory хранилище
```

Покрыто: загрузка конфига, разбор xlsx, генератор вопросов (дубликаты значений, списковые поля, границы числа
вариантов, тысячи случайных вопросов с проверкой «ровно один правильный»), весь сценарий бота — тур от начала до
итога, досрочное завершение, неверный ввод числа, повторное и устаревшее нажатие, произвольный текст в каждом
состоянии, картинки и кэш `file_id`.

## Структура кода

| Папка | Назначение |
|---|---|
| `src/Quiz` | Конфиг тем и генератор вопросов, без зависимости от фреймворка |
| `src/Import` | xlsx → проверка → база (`ThemeImporter`) |
| `src/Bot` | Автомат раунда (`BotHandler`), экраны, хранилище (`QuizStore` и Doctrine-реализация) |
| `src/Telegram` | Шлюз к Bot API (`TelegramGateway`), модель апдейта |
| `src/Entity` | `quiz_theme`, `quiz_item`, `quiz_mode_stat`, `quiz_telegram_file`, `quiz_player`, `quiz_round` |
| `src/Command` | `app:quiz:import`, `app:telegram:poll`, `app:telegram:webhook`, `app:quiz:close-idle` |
